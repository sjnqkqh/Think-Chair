# Agentic RAG 자료 인덱싱 설계

## 목표

PR 01에서 수집한 `FetchedSource`를 다시 웹에서 가져오지 않고 재사용할 수 있게
원문, 출처 정보, 검색용 벡터를 함께 저장한다. 검색과 답변 생성은 후속 PR에서
다룬다.

## 고정값

- 임베딩: OpenAI `text-embedding-3-small`, 1536차원
- 벡터 저장소: 로컬 영속 Chroma
- 청크: 최대 600토큰, 인접 청크 100토큰 중첩
- 청킹 규칙: `chunk-600-100-v1`
- 컬렉션: `research_public_v1`, `research_private_v1`

공개 자료와 비공개 자료는 컬렉션부터 분리한다. 각 컬렉션 안에서는 한국어,
영어, 혼합 언어를 같은 임베딩 공간에 저장한다.

## 구조 우선 청킹

입력이 마크다운이라고 가정하지 않는다. 원문을 Unicode NFC로 정규화한 뒤
다음 순서로 가능한 경계를 사용한다.

1. 빈 줄로 구분된 문단
2. 줄바꿈
3. 한국어·영어 문장부호
4. 공백
5. 문자

위쪽 경계로 600토큰 이하를 만들 수 없을 때만 다음 경계로 내려간다.
페이지 본문과 Reddit 댓글·답글은 서로 다른 구역으로 나누어 청킹한다.

각 청크는 `source_id`, 청킹 규칙, 순번, 본문 해시로 결정적인 ID를 만든다.
따라서 같은 자료를 재시도하면 Chroma `upsert`가 기존 벡터를 덮어쓰며
중복을 만들지 않는다.

## 출처와 원문

모든 벡터 메타데이터에 `source_id`, 대표 URL, 해당 구역의 URL, 본문 해시,
언어, 청크 순번과 시작 위치를 저장한다. Reddit 댓글은 대표 글 URL과 댓글
고유 주소를 함께 가진다.

수집 결과 전체는 기간 만료 없이 `research_sources/{source_id}.json`에 보관한다.
임베딩 모델이나 청킹 규칙이 바뀌면 이 파일로 새 컬렉션을 만들며 웹 문서를
다시 수집하지 않는다. 같은 URL은 갱신 여부를 확인하지 않고 기존 자료를
그대로 사용한다. 삭제·정책 위반 자료는 원문과 벡터를 함께 제거하고
`tombstoned` 상태로 다시 등록되지 않게 막는다.

## 중복과 접근 범위

- 공개 자료: 대표 URL 기준으로 프로젝트 전체에서 한 번만 저장한다.
- 비공개 자료: 사용자와 원고 범위 안에서만 중복을 제거한다.
- 요청 URL이 기존 대표 URL로 이동한 경우 요청 URL 별칭만 기존 자료에 연결한다.
- 서버가 결정한 `public | private | reject` 정책만 저장 범위를 선택한다.

URL은 PR 01이 검증·정규화한 값을 그대로 사용하고 별도의 의미 추론이나
추적 매개변수 제거는 하지 않는다.

## 실패와 재시도

자료 상태는 `pending → indexed | failed`로 기록한다. 임베딩이나 Chroma 저장이
실패하면 해당 시도에서 만든 벡터와 원문을 정리하고 `failed`로 남긴다. 같은
입력을 다시 처리하면 결정적인 ID로 재시도한다.

SQL, 파일, Chroma를 하나의 트랜잭션으로 가장하지 않는다. 각 저장소의 보상
삭제와 멱등적인 ID로 일관성을 회복한다.

## 제외 범위

- 유사도 검색과 답변 인용
- 임베딩 공급자 자동 선택
- 동일 URL의 변경 감지·재수집·버전 기록
- 키워드 검색, reranker, 지식 그래프

## 완료 조건

- 구조 우선 600/100 청킹이 한국어·영어·혼합 원문에서 토큰 제한을 지킨다.
- 같은 URL과 같은 자료를 재처리해도 원문·청크·벡터가 늘지 않는다.
- 모든 청크에서 대표 출처 URL까지 추적할 수 있다.
- 공개 자료는 전역 재사용되고 비공개 자료는 별도 컬렉션과 소유자 정보로 격리된다.
- 모델·차원·청킹 규칙이 다른 기존 컬렉션을 열면 명시적으로 실패한다.
