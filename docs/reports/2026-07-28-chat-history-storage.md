# 채팅 이력 저장소 분석

## 결론

사용자 화면의 대화 이력은 `ChatMessage`를 기준으로 삼고, LangGraph 체크포인트는
그래프 실행 상태와 내부 컨텍스트로만 유지한다. `ChatMessage`가 없는 원고는
빈 대화 이력으로 표시하며 체크포인트를 UI 이력으로 사용하지 않는다.

## 확인된 원인

- 워크스페이스 재접속 화면은 `ChatMessage`가 아니라 체크포인트의 `messages`를
  읽고 있었다. 따라서 두 저장소가 어긋나면 DB에 저장된 메시지도 화면에서
  누락될 수 있었다.
- `ChatMessage` 저장 시 `SQLAlchemyError`를 삼키고 메모리 객체를 반환했다.
  이 경우 현재 스트림에서는 메시지가 보이지만 DB에는 남지 않아 재접속 후
  조용히 사라질 수 있었다.
- 두 저장소의 메시지는 역할이 달라 개수가 항상 같을 필요가 없다. 예를 들어
  문서 생성 안내는 UI 이력에만, 그래프 내부 응답은 체크포인트에만 존재할 수
  있다.

## 데이터 근거

로컬 저장소의 본문을 출력하지 않고 원고·메시지 개수만 집계했다.

- 전체 원고: 60개
- `ChatMessage` 보유 원고: 41개
- 체크포인트 보유 원고: 52개
- 체크포인트에만 이력이 있는 원고: 11개
- 두 저장소의 메시지 개수가 다른 원고: 9개

## 이번 변경

- 워크스페이스 이력을 `ChatMessage.sequence` 순서로 조회한다.
- `ChatMessage`가 0건이면 빈 대화 이력을 표시한다.
- 저장 오류를 성공처럼 처리하지 않고 호출자에게 전파한다.
- LangGraph 노드, 체크포인트 정책, DB 스키마는 변경하지 않는다.

## 후속 검토

부분적으로 불일치한 과거 이력을 자동 병합하지 않는다. 두 저장소 사이에
공통 메시지 ID가 없어 본문 기반 병합은 중복·오정렬 위험이 있다. 모든 과거
이력을 `ChatMessage`로 통합하려면 별도 백필 규칙과 검증 절차를 정한 뒤
일회성 마이그레이션을 수행해야 한다.
